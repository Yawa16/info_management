# HOPE, Inc. ERP
# Team Working Agreement, Definition of Done, and Role Guide

## 1. Team Working Agreement

The HOPE, Inc. ERP development team agrees to follow these guidelines throughout the project.

### Communication
- Team members must communicate regularly about their progress.
- Members should inform the Scrum Master about blockers or difficulties.
- Questions and concerns should be communicated respectfully.
- Important project decisions must be documented in GitHub.

### Collaboration
- Team members must complete their assigned tasks.
- Members should coordinate when their tasks depend on another member's work.
- Everyone should review relevant changes before they are merged.
- Team members should help each other when issues arise.

### GitHub Workflow
- Every assigned task must have a corresponding GitHub Issue.
- Developers must create branches for their assigned tasks.
- Changes must be submitted through Pull Requests.
- Pull Requests must include a description of the changes and reference the related issue.
- Required reviews and checks must be completed before merging.
- Completed tasks must be updated on the Sprint 1 Project Board.

### Professional Conduct
- Respect everyone's opinions and contributions.
- Avoid making changes to another member's work without coordination.
- Meet agreed deadlines.
- Take responsibility for assigned tasks.

## 2. Definition of Done (DoD)

A task can be considered Done when it meets the following criteria:

- [ ] The assigned requirements have been completed.
- [ ] The implementation matches the task description and acceptance criteria.
- [ ] The code or deliverable has been reviewed.
- [ ] Relevant tests have been performed.
- [ ] Identified issues have been addressed.
- [ ] Documentation has been updated when necessary.
- [ ] The Pull Request has received the required approvals.
- [ ] The changes have been successfully merged into the appropriate branch.
- [ ] The GitHub Issue and Project Board status have been updated.

A task should not be marked Done if important requirements remain incomplete or unresolved.

## 3. Team Roles and Responsibilities

### Scrum Master
- Organizes and maintains the Sprint Board.
- Creates and organizes user stories and sprint tasks.
- Monitors task progress.
- Coordinates team communication.
- Helps identify and resolve blockers.
- Facilitates sprint reviews and retrospectives.

### Developer
- Develops and maintains application features.
- Implements assigned user stories and requirements.
- Connects application features to the database.
- Fixes reported bugs.
- Creates Pull Requests for completed work.

### Database Administrator (DB Admin)
- Designs and maintains the database structure.
- Creates and manages database tables and relationships.
- Prepares database migrations and sample data.
- Maintains database documentation.
- Supports developers with database-related concerns.

### UI/UX Designer
- Designs application layouts and wireframes.
- Establishes the design system and reusable components.
- Creates interface mockups.
- Ensures the interface is understandable and consistent.
- Updates designs based on feedback.

### Tester
- Prepares test plans and test cases.
- Tests application features against acceptance criteria.
- Identifies and reports bugs.
- Verifies fixes submitted by developers.
- Reports testing results to the team.

## 4. Team Agreement

All members agree to follow the working guidelines, fulfill their assigned responsibilities, communicate regularly, and contribute to completing the HOPE, Inc. ERP project.
