Main page and User Management

Task 3 · Mid-fidelity · Static previews at desktop 1440px, tablet 768px, and mobile 375px. Uses Task 1 tokens and component patterns. Sample records are illustrative; this sheet is not functional authentication or account-management software.

Assumptions

Roles are Superadmin, Admin, and User. Statuses are Active, Inactive, and Blocked. Deleted is a soft-delete view, not an account status.

Superadmin manages all users and can assign User or Admin. Admin manages Users and can create Users only; Admin/Superadmin records are read-only. User has no User Management access.

Delete is recoverable; Deleted rows remain visible and can be restored. No permanent-delete action is shown.

Add user creates an approved account with an Admin-entered temporary password; the account holder must change it at first sign-in. Admin can create Users; Superadmin can create Users or Admins. The current creator only supports Users, so Admin-role creation needs implementation support.

No other business modules or dashboard metrics are named in the project context, so none are invented here.

At 768px and below, navigation uses the Task 1 drawer pattern. The drawer is closed by default and opens from the menu button.

Flow overview

Login→Home→User Management→View / Add / Edit dialog→ SaveList updates + User saved Block / Delete→ confirmation →Updated status / Deleted tab Restore→ confirmation →Restored row User role → No access → Back to Home

Product-owner decisions

  1. Accounts created by Admin or Superadmin are approved immediately. Admin can create User accounts; Superadmin can create User or Admin accounts. Created users must change the temporary password at first sign-in.
  2. Add requires a confirmation before account creation. The Admin shares the temporary password securely after creation.
  3. Mixed bulk actions apply only to eligible rows and report the eligible count before confirmation.
  4. Restore preserves the account’s prior status.
  5. At and below 768px, use the Task 1 navigation drawer. Desktop sorting remains Last edited descending; mobile uses stacked cards. Users do not edit their own profiles in this task.
